Settlement Check

A prediction market is a claim about the future.
This asks what will decide it — and whether anyone can check that.

Measured on the live Panta catalogue, and checked against Panta's own front end. Every number here comes from the snapshot below it; nothing on this page is typed by hand.

What settles a market, read from the chain rather than from a field

The oracle field reads like the account that decides a market. It is not: on every market checked it names the wallet whose instruction is CreateEventUsdc, which creates markets and does not resolve them.

On chain, every result in this snapshot was submitted and every event resolved by 664h8sZvGwUx4hfqWYrewwvC7wenbKPTCFQTKZx5ghbR — an account owned by the System Program, holding no data. A person with a key, not a program. No UMA program appears in any of those transactions.

The settlement path is GraduateMarket → SubmitOracleResult → ResolveEvent → ClaimWin, and it arrives under two naming families: markets carrying a MigrateEventV2 settle without the Usdc suffix, the rest with it. Matching one and not the other — which this tool did at first — reports a settled market as one that nothing has settled.

sentToUma is true on 34 of the 40 markets here. That is a field in the API, not something the venue tells its users: its page says agent resolution, with a confidence score, a written rationale and a dispute window. The report puts the flag and the signature side by side and concludes nothing further.

Before you publish: the same rules, on a draft

Panta's create API requires a question, a resolutionRule of up to 2048 characters and a non-empty sourcesOfTruth. A complete card returns them; a stripped one returns none of them. oracle is sourcesOfTruth joined by commas — which is why the most common settlement source in this catalogue is the word on-chain, typed into that list by a creator.

--check-draft refuses a draft a buyer could not read, then hands it to Panta's own validator and reports the real creation fee. Nothing is signed, submitted or paid.

a draft shaped like the catalogue

6 thing(s) would leave a buyer unable to read this market
  BLOCK question: no question
        → state what is being bet on, in one sentence
  BLOCK sourcesOfTruth: 'on-chain' is a word, not a reference
        → name the account, the program or the outlet. A buyer sees this string and nothing else — it becomes the market's `oracle` field verbatim
  BLOCK endTime: trading would close before it opens
        → startTime must be earlier than endTime
  BLOCK resolutionTime: the market resolves before trading ends
        → resolutionTime must be at or after endTime
  BLOCK startTime: starts in 0s; the chain requires 3600s
        → move startTime further out, or declare it a breaking market in progress
  BLOCK imageUrl: points at a private address
        → host it somewhere a reader can reach
  WARN  resolutionRule: 8 characters
        → a rule this short rarely names both the measurement and the moment it is read; nobody can see this field after publication, so it is the creator's only record

Live: the same check, as settlements land

./run.sh --watch subscribes to the market program and reports each settlement the moment it arrives — which market closed, what the catalogue claimed would decide it, and who signed. --replay runs the same code over a settlement that already happened.

          market   4J96MvCVb1MYMotdNbyj1yFKDXQp7UJhLYUMJLPhXRQN
          claimed  world-stocks-bloomberg,world-stocks-nyse,world-finance-yahoo
          the catalogue says this one went to UMA
          signed   664h8sZvGwUx4hfqWYrewwvC7wenbKPTCFQTKZx5ghbR
          → a claim of UMA, settled by a signature, with no UMA assertion in the transaction

Measured, not asserted: Solana's public node accepts a logsSubscribe with a program filter, acknowledges it, then closes the connection; and reading the settlements already in the catalogue exhausts it at a couple of dozen markets with getTransaction failed after 3 attempts. The watcher reconnects and, when it gives up, says that is the endpoint's limit and not the venue having nothing to settle. SOLANA_WS points the same code at one that will hold it.
